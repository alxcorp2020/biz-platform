# Phase 3 요구사항: 파이프라인 칸반/표 (구현 완료)

작성일: 2026-08-02 (요구사항 확정) / 구현: 2026-08-02
상태: 구현 완료 — 로컬 검증 완료(빌드/vet/test, curl, 헤드리스 브라우저)

## 배경

현재 `#/pipeline` 화면(`collector/internal/webui/static/index.html`
`renderPipelineList()`)은 칸반이 아니라 상태별로 그룹핑된 **평면 리스트**다.
`PIPELINE_STATUS_LIST` 순서대로 섹션을 나눠 보여주고, 정렬은 API가
`submission_deadline ASC NULLS LAST`로 고정 처리한다. 이 문서는 그 위에
칸반/표 뷰를 추가하는 작업의 요구사항만 정리한 것이며, 구현은 아직
시작하지 않았다.

## 상태값 (참고)

`notice_pipeline_entries.status` CHECK 제약(`db/migrations/001_init.sql`):
`검토전 / 참여검토 / 승인대기 / 준비중 / 제출완료 / 낙찰 / 탈락 / 보류 / 제외`

- 진행중 4개: 검토전, 참여검토, 승인대기, 준비중
- 종결 5개: 제출완료, 낙찰, 탈락, 보류, 제외

자동전환 배치(`collector/internal/api/pipeline_auto_transition.go`)가 매일
진행중 4개 상태 중 마감일이 지났거나(`submission_deadline < CURRENT_DATE`)
연결된 공고가 마감/취소된 건을 자동으로 `제외`로 전환한다.

## 확정된 요구사항

1. **뷰 구성**: 기존 `#/pipeline` 화면에 **리스트 / 칸반 / 표(엑셀형 테이블)**
   3가지 뷰 토글을 추가한다. 기존 리스트 뷰는 그대로 유지(대체하지 않음).

2. **칸반 컬럼**: 진행중 4개 상태만 컬럼으로 쓴다(검토전 / 참여검토 /
   승인대기 / 준비중). 종결 5개 상태(제출완료 / 낙찰 / 탈락 / 보류 / 제외)는
   칸반 컬럼에 넣지 않고, 칸반 하단에 **접이식 '종결됨' 섹션**으로 모아서
   보여준다.

3. **드래그앤드롭**: 칸반 카드를 드래그해서 컬럼(상태)을 바꾸면 상태변경
   API를 호출한다. 마감일이 지났거나 공고가 마감된 건(자동전환 대상)도
   드래그 자체는 허용한다 — 기존 자동전환 배치 로직은 그대로 유지하며,
   드래그로 인한 특별 예외처리는 추가하지 않는다(사용자가 수동으로 옮겨도
   막지 않되, 다음 배치 때 조건에 해당하면 다시 자동으로 '제외'로 넘어갈
   수 있음).

4. **칸반 카드 정보**: 제목 + 발주기관 + 담당자 + 마감일(D-day) + AI판정등급.
   예산은 카드에 넣지 않고 상세화면에서만 유지한다(기존과 동일).

5. **표 뷰**: 칸반과는 별개인 세 번째 뷰. 엑셀형 테이블로, 진행중 +
   종결 상태 전부를 한 화면에 행으로 보여줄 수 있어야 한다.

6. **모바일 대응**: 칸반/표 뷰는 **PC 전용**이다. 모바일에서는 뷰 토글
   자체를 숨기고 기존 리스트 뷰만 제공한다.

## 착수 전 확인했던 두 가지 (결론)

1. **표 뷰의 정확한 컬럼 구성** — 사용자와 재확인해 8개 컬럼으로 확정:
   공고명/발주기관/상태/담당자/마감일/AI판정등급/서류미비 건수/최근수정일.
   정렬은 헤더 클릭, 필터는 상태별 드롭다운.
2. **드래그앤드롭 상태변경에 기존 API를 재사용할 수 있는지** — 코드
   확인 결과 `PATCH /api/pipeline/{id}`가 이미 부분수정(부분 필드만
   보내면 그 필드만 바뀜)을 지원하고 상태 전이 제약도 없어서, 새
   엔드포인트 없이 `{status: 새상태}`만 보내는 것으로 그대로 재사용했다.

## 구현 내역

- **백엔드** (`collector/internal/api/company_pipeline.go`): `pipelineEntry`에
  `AIGrade` 필드 추가, `attachPipelineGrades()`가 `GET /api/pipeline` 응답에
  대해 growth_analytics.go의 `fetchGradeDistribution`과 동일한 방식으로
  요청 시점에 `scoreNoticeForCompany`를 호출해 채운다(영속 컬럼 아님).
  상태변경은 기존 `PATCH /api/pipeline/{id}` 그대로 재사용.
- **프론트엔드** (`collector/internal/webui/static/index.html`):
  `renderPipelineViews`가 리스트/칸반/표 뷰 토글의 공용 껍데기 — API는
  한 번만 호출하고 뷰 전환 시 재요청 없음. 칸반은 HTML5 드래그앤드롭
  (`dragstart`/`dragover`/`drop`)으로 낙관적 갱신 후 PATCH 호출, 실패
  시 원래 컬럼으로 롤백. 모바일(≤640px)은 뷰 토글을 숨기고 리스트로
  강제하며, 이미 데스크톱에서 칸반/표를 보던 중 창을 좁혀 640px 아래로
  넘어가는 경우까지 대응하는 전역 `resize` 리스너를 추가했다(이 SPA에서
  유일한 resize 리스너 — 다른 화면은 라우트 전환 시 매번 새로 그려지므로
  불필요).
- **검증**: `go build/vet/test` 통과, curl로 `aiGrade` 필드 확인 및
  PATCH 재사용 확인, 헤드리스 브라우저로 리스트/칸반/표 3뷰 렌더링,
  칸반 드래그앤드롭 성공/실패(네트워크 차단 후 롤백+에러 알림) 양쪽,
  종결됨 접이식 섹션, 표 정렬/필터, 모바일 뷰 토글 숨김(초기 로드 +
  라이브 리사이즈) 전부 확인.
